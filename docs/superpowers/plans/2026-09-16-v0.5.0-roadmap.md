## 候选下一刀 (按价值/依赖排序)

### 候选 A: Agent Security / Governance (推荐先打, 面试最稀缺)
- RBAC (角色/资源/动作矩阵) 扩展现有 `security/policy.py`
- ABAC (属性/租户/部门/permission) 端到端
- Tool Permission 收紧: 谁可调 db.query / restart / deploy
- Secret Management: 真 key 不入 env, 走 vault/secret manager stub
- Sandboxing: Tool 执行隔离 (subprocess/容器级别)
- Prompt Injection 防御层: 输入审计 + 工具白名单
- Tool Injection 防御: tool 输出二次审计
- Data Exfiltration 检测: 跨 tenant/permission 越权读阻断
- Agent Identity: 任务级审计 trail (复用 v0.4.0 AgentTask.history)
- 预期 spec: 1-2 个, 估 40-60 测试

### 候选 B: 真 PG 杀进程跨重启恢复 (v0.2.0 遗留)
- 确认远程 PG 库名 (`192.168.80.156`, admin/123456)
- 安装 `langgraph-checkpoint-postgres` + 真 PG 跑 `PostgresSaver`
- 模拟进程 kill → 新进程实例同 `thread_id` resume → 验证从 judge 后不重跑 fetch
- 当前 v0.2.0 release note 诚实声明的"未验证"项, 是企业级门面真正闭环的一步

### 候选 C: Multi-Agent 协作
- Supervisor + Specialist 拓扑 (Log/Metric/Code/Knowledge/Analyst)
- 故障排查场景: Metric Agent + Log Agent + Code Agent + Knowledge Agent → Analyst Agent 综合 → Report
- Agent 间通信 (handoff/共享 context)
- 依赖 v0.3.0 Memory (跨 agent 共享), 估 50-80 测试

### 候选 D: Workflow 深化 (Saga / Compensation / Durable Execution)
- 报销审批完整 Saga: Step1 读 → Step2 校验 → Step3 审批(可暂停) → Step4 创建付款 → Step5 验证
- Compensation: 失败时反向补偿 (撤销已发付款)
- Event Sourcing: 每个状态变更记 event
- 依赖 v0.2.0 checkpoint + v0.4.0 AgentTask, 估 40-60 测试

### 候选 E: OTel / Prometheus 替换内存 Tracer
- OpenTelemetry SDK 接入 (OTLP exporter)
- Prometheus metrics 暴露 (FastAPI `/metrics`)
- Span/Metric 命名对齐语义约定 (task span, llm span, tool span)
- 替换 `observability/tracing.py` 内存版
- 依赖 v0.4.0 已有 task_status_changed 事件, 估 20-30 测试

### 候选 F: EpisodicMemoryProvider 真实现
- 事件溯源: 每次 Task 状态变化写 episodic row
- 跨任务检索: "上周有过类似故障吗?"
- 依赖 v0.4.0 AgentTask.history + v0.3.0 memory schema, 估 15-25 测试

### 候选 G: 多场景落地 (运维 → 合 / 合规 → 分析)
- 接 scm-platform (同级仓库) 做端到端 IT 运维场景
- 接企业内部文档做合同合规场景
- 接 BI/DB 做销售分析场景
- 估 60-100 测试, 跨仓

## 优先级建议 (按企业级生产主线)
1. **候选 A (Security)** — 企业级面试最稀缺 + 真实生产必过
2. **候选 B (PG 杀恢复)** — 闭环 v0.2.0 遗留, 验证真 PG
3. **候选 D (Saga)** — 加深 v0.4.0 AgentTask 价值
4. **候选 E (OTel)** — 把内存可观测换企业级
5. **候选 C (Multi-Agent)** — 复杂场景扩展
6. **候选 F (Episodic)** — 小步快走补洞
7. **候选 G (多场景落地)** — 终极产品化

## v0.5.0 候选切分

- 若走"补漏闭环"路线: v0.5.0 = 候选 B (PG 杀恢复)
